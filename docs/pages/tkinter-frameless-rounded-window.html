Tkinter, frameless, rounded and translucent — on Windows

Tk can do none of these three things by itself. All three are two lines of ctypes away, and all three have a trap that will cost you an afternoon if nobody tells you first.

This is the technique used by Plan Card, a desktop plan card written with nothing but the standard library. The whole thing depends on the standard library being enough, so everything below is stdlib-only: no pywin32, no third-party packages.

1. Frameless

root = tk.Tk()
root.overrideredirect(True)

That is it — no title bar, no borders, no taskbar button. On Windows the window manager stops treating it as a managed window.

What breaks immediately

  • You cannot close it. There is no X. Add a close control, or a key binding, before you ship.
  • You cannot move it. Implement drag yourself: bind <Button-1> on your header, remember the offset, and call geometry("+x+y") on <B1-Motion>.
  • No Alt+Tab, no taskbar. The window is invisible to window switching. If it gets buried under a maximised window, the user has to minimise that window to find it.
  • No focus by default. Because nothing is activated, the window may not receive keyboard events until clicked.

2. Translucent

root.attributes("-alpha", 0.9)   # 0.0 – 1.0

The trap: -alpha applies to the entire window, text included. At 0.9 nothing is noticeable; at 0.6 your labels get soft too. If you want a truly transparent background with opaque text, the usual alternative is -transparentcolor, which punches a colour key through the window — but it produces hard, aliased edges around rounded shapes and text, so most people come back to -alpha and accept slight text softening.

One more thing worth knowing: on a layered window the alpha can be animated. Plan Card fades in by stepping from 0.0 to the target opacity in a root.after(16, ...) loop, which takes about a sixth of a second.

3. Rounded corners

This is the one that is not obvious. Tk draws rectangles; Windows decides the shape of the window. You have to tell Windows to clip it:

import ctypes

def round_region(win, w, h, r=18):
    hwnd = ctypes.windll.user32.GetParent(win.winfo_id()) or win.winfo_id()
    rgn = ctypes.windll.gdi32.CreateRoundRectRgn(0, 0, w + 1, h + 1, r, r)
    ctypes.windll.user32.SetWindowRgn(hwnd, rgn, True)

The three traps

  • GetParent. Tk on Windows wraps your widgets in a container window, so winfo_id() is usually not the top-level handle you want to clip. GetParent(...) or ... covers both cases.
  • w + 1, h + 1. The region is exclusive at the right and bottom edge. Without the extra pixel you get a one-pixel sliver of the window showing on two sides.
  • Re-apply on resize. The region is a snapshot: if the window grows, the new area is not clipped. Call round_region again after every size change, not just at startup.

4. Drawing rounded shapes inside the window

The window region clips the outside. Cards, buttons and chips inside the window are drawn by you. Tk has no rounded rectangle primitive, but a smoothed polygon with duplicated corner points is close enough that nobody can tell:

def rounded(canvas, x0, y0, x1, y1, r, **kw):
    pts = [x0 + r, y0, x1 - r, y0, x1, y0, x1, y0 + r,
           x1, y1 - r, x1, y1, x1 - r, y1, x0 + r, y1,
           x0, y1, x0, y1 - r, x0, y0 + r, x0, y0]
    return canvas.create_polygon(pts, smooth=True, **kw)

Each corner repeats its control point, which pulls the spline tight into a quarter-circle. It is the same trick every Tk rounded-widget snippet uses, and it scales to any radius.

The order that works

  1. overrideredirect(True)
  2. build the UI, then let Tk compute the real size (update_idletasks())
  3. fit the height, then call round_region with the final size
  4. set -alpha last, and fade in

Getting the region before the window has its final size is the single most common bug: the corners are correct for a height the window no longer has.
