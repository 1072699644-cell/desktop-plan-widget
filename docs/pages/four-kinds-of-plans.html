Why your plan list should be four lists

Most plan documents fail for the same boring reason: a habit you do every morning, a deadline in March, a project with no end date and an idea you had in the shower are all sitting in the same column, pretending to be the same thing.

The one-list failure mode

You start a list. Day one it has eight items. Day three you add a big goal that will take two months. Now the eight small things and the two-month thing sit at the same visual weight. The small ones get checked, the big one never does, and after a week the list is a wall of stale rows that you stop opening.

The list did not fail because you lack discipline. It failed because it asked one column to do four jobs.

The four jobs

1. Daily — repeated, resettable

A thing you either did today or did not. Drink water. Read thirty pages. It has no end date and no percentage; the only meaningful question is "did it happen today". The list should reset every morning and keep a record of the days you clicked, so the history accumulates while the checklist does not.

Behaviour: one button per row, a streak, a rate over the last thirty days.

2. Stage — finite, dated

Something with a deadline: an exam on the 14th, a thesis defence, a trip you are saving for. Here the useful number is not a percentage, it is how many days are left, and after the date passes, how many days late it is.

Behaviour: pick a date from a calendar, show 60d, then Today, then 3d late. No percentage, because "70% of a thesis" is a number you will invent rather than measure.

3. Long-term — open-ended, measurable

No deadline, but real progress: learn a piece all the way through, save ten thousand, get fit enough for a half marathon. There is no finish date to count down to, so the only honest signal is how far along you are.

Behaviour: a percentage you set yourself, updated by hand. It is an estimate, and that is fine as long as everyone involved knows it is one.

4. Future — not yet work

Someday / maybe. Ship a side project. Learn to sail. These are not tasks; they are candidates. They should be visible enough to review occasionally and cheap enough to ignore the rest of the time.

Behaviour: deliberately no percentage and no countdown. The moment you give a someday-idea a deadline, it becomes a Stage row and starts generating guilt.

A worked example: pass the driving test

  • Daily: practise the theory app for 15 minutes.
  • Stage: pass the written test on the 21st — countdown, then late.
  • Long-term: forty hours of practical driving — a percentage.
  • Future: buy a car — no percentage, no date, not yet.

Four lists, one goal. If you had put those in one column, "buy a car" would sit between "practise theory" and "pass the test" and look equally urgent.

Things move between lists

The lists are not fixed boxes. A future item gets a date and becomes a stage. A stage item with the deadline removed becomes long-term. A long-term item that turns out to be daily becomes a habit. Most plan tools cannot express this because they only have one list, so in practice people just delete and retype.

The test for a plan system is not how many fields it has. It is whether moving an item from "someday" to "due in March" is one action or a retype.

This is the shape of Plan Card

Plan Card is a desktop card with exactly these four sections, because the tool was built around the method rather than the method being fitted to the tool. Each section behaves the way its rows require: resets, countdowns, percentages, and nothing at all. It is described on the front page, and you can see all four in the five themes.
